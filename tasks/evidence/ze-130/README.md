## Source evidence

- `crates/zeppelin-embed/Cargo.toml` declares timing, allocation-audit and test-support features, but no graph feature. `crates/zeppelin-embed/src/lib.rs:62` exports `property_graph` unconditionally. A complete `rg -n property_graph crates/zeppelin-embed/src --glob '!**/property_graph/**'` yields only that module export. The current native graph implementation is structurally isolated from existing legacy core modules, so its feature boundary does not require the unfinished coordinator.
- `crates/zeppelin-embed-ffi/Cargo.toml` declares empty `graph-cypher=[]`; it does not select core graph or the compiler. The existing `graph-result-test-support` feature is separately explicit. `src/lib.rs:3912` already rejects graph FFI on unsupported OS/architecture, while core has no matching graph selection guard.
- `crates/zeppelin-embed-cypher/Cargo.toml` directly depends on the core and the compiled binder/lowerer already imports native graph values/plans. An internal dependency feature can select that real core component; core must never depend back on the compiler.
- `tests/Cargo.toml` currently depends on the compiler unconditionally and its graph-cypher flag enables only the FFI test hook. Core graph integration files and most PG runner registrations currently compile unconditionally. They must move coherently with the production feature boundary; legacy ANN tests are distinct and cannot be disabled by a graph_* filename rule. A Cargo workspace selecting the compiler can unify graph features, so it cannot prove a standalone legacy artifact is graph-free.
- ZE-67 already supplies `cbindgen.graph.toml`, separate generated graph data contracts and `ffi_graph_header.rs` drift/layout/legacy-absence checks. These intentionally declare no unavailable graph runtime C functions. The existing header is not a completed graph runtime artifact.
- `scripts/release/core_header.py` removes an exact optional-text inventory; its fail-loud inventory checks must remain. `scripts/macos-sdk/build.sh` and `scripts/xcframework/build.sh` produce existing legacy artifacts with hard-coded identities/targets; `Package.swift` and `.github/workflows/swift-release.yml` currently select one legacy binary identity and literal remote checksum. Their complete graph counterparts remain ZE-107/71 rather than publishing empty runtime promises now.
- `scripts/size-budget.sh` measures current core/FFI archives and a minimal legacy consumer. It cannot establish reachability or complete graph+compiler size merely by selecting a dependency. ZE-107 must still report real early section/archive/consumer totals and unimplemented reachability as lower bounds; final complete graph+compiler 5120KiB and legacy gates remain mandatory.

Installed Rust standard-library targets include aarch64-apple-darwin, x86_64-apple-darwin, x86_64-pc-windows-msvc and x86_64-unknown-linux-gnu. This makes genuine compile-time unsupported-target checks possible without treating a missing target library as the intended failure. It is not native Windows/Intel/minimum-macOS runtime evidence.
