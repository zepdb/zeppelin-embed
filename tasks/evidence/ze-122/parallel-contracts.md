## Adjacency seam (ZE-124 → ZE-44)

The storage owner reviewed this seam against ongoing ZE-43 tree/payload/private-pack code. Adjacency kernels use landed strong full-u128 NodeId/RelId, RelTypeId, explicit Out/In, a half-open [lower,upper) RelId range with a distinct infinity tag, borrowed immutable base/delta bytes, caller-owned bounded output, and a fallible per-work checkpoint. They do not require moving TreeBlockSource/Sink/StorageMemory APIs, native view construction or VFS publication.

A base has at most4096 sorted unique (RelId,other NodeId) entries. A delta preserves both IDs, insert/delete action and committed sequence; at most8 runs and2048 pending entries are admitted before private consolidation/splitting. Every run binds exactly the same node/type/direction/range. Validate the entire input, including reserved bytes, count/geometry, full numeric ID order, uniqueness, range membership and compatible sequences, before emitting the first result. Sequences use the native WAL u64 commit sequence, distinct from GraphGeneration. A base/range carries an explicit consolidation watermark; merge input includes a committed cutoff. Require watermark <= cutoff and watermark < each delta sequence <= cutoff, with nondecreasing run sequence order. Exact equal-sequence duplicate observations may coalesce; inconsistent actions are corruption. Every occurrence of a RelId across all supplied sequences/base must preserve the same neighbor identity, even when a newer delete wins. Newest valid sequence wins; deletes cannot conceal topology corruption. The ZE-44 adapter binds these primitive watermark/cutoff values to the real admitted root and validates cross-group authoritative topology. Empty ranges disappear, output ranges remain nonoverlapping, and u128::MAX never requires arithmetic wrap. Property-only edits produce no adjacency change.

The implementation owns one hand-written inner format/version with exact byte goldens. Append-only outer tags13/14 are reserved for adjacency base/delta; ongoing ZE-43 owns11/12 for payload chunk/provenance. These blocks fit direct PhysicalRef storage; do not widen unrelated PayloadRef role admission. A range descriptor can retain at most8 delta references plus a base inside the existing compact tree value bound. Exact persisted offsets and typed constructor signatures are reviewed in the ZE-124 commit before ZE-44 consumes them.

The codec/merge itself allocates no hidden backing. Use a compact nonallocating typed inner error and carry the caller control error without inner formatting; main FormatError owns a String and is not allocation-free. Do not call the current uncontrolled outer decoder and claim it is cancellable: the real storage adapter admits outer framing and owns that proof. Callers retain input/output/scratch ownership for the operation. Any state/scratch used by the real integration is included in the authentic storage32MiB/writer64MiB/shared256MiB accounting. Checkpoint each actual entry and bounded comparison/copy work, never after more than64KiB of byte work. Typed malformed/limit/control errors never return a valid partial result; private partially written scratch must be discarded. The integration adapter maps actual work into query/write counters and preserves close-first cancellation when reading an admitted view.

ZE-124 must prove thresholds, split/merge order, full IDs, cancellation, corrupt runs and independent edge-oracle controls. ZE-44 must still prove exact actual OUT/IN agreement with authoritative relationship updates, same-batch endpoint validation, self/parallel edges, both-endpoint liveness and all-or-none roots using the real ZE-43 producer. Whole-participant missing-reverse detection cannot be replaced by comparing two synthetic arrays. ZE-45/47 retain actual lease, file/recovery and fault qualification.

## Completed values and C ownership (ZE-127/128 → ZE-53/68)

The native owner uses bounded typed arrays/checked indices for rows, values, lists, strings and copied graph records/reports. Preserve full IDs, exact bits, labels/properties, endpoints/type/revision/key/last generation. Default copied entities exclude text/vector unless explicitly selected; stored-text expression results are independent copies. No recursive neighbors, lazy lookup, foreign/caller/view borrow, or query/store lifetime parameter survives into final application-owned results.

A prepared native owner retains real query/shared charges for actual capacities; final consuming transfer moves backing without allocating or copying and releases only authentic temporary accounting exactly once. Element representations must be owned; a generic escape hatch for borrowed QueryValue is forbidden. Core/ABI each retain4MiB represented limits,65536 rows, plus measured control/registry backing and simultaneous query24MiB/writer64MiB/shared256MiB overlap. The exact compiled native builder/detach API is single-owned by ZE-127 and reviewed before conversion.

ZE-128's real C allocator guarantees alignment through actual typed backing/Layout, charges padding/full capacity and preserves correct deallocation layout. ZE-37 Vec<u8> backing is not an aligned typed arena contract. Reserve actual registry backing and slot/token before the commit boundary; HashMap insertion/logical capacity alone is not that proof. Prepared registration authenticates the entire root/pool geometry. Expose is an infallible move of prepared ownership, with no allocation/copy/formatting/callback/growth. Free validates token/type/generation/pointers/counts against authoritative ownership, then drops one bounded allocation set; it never traverses host-mutated recursive pointers. Empty second free is harmless; stale/forged/cross-kind descriptors cannot steal the live owner.

The outcome cell remains outside unwind, enters Indeterminate before a potentially committing call and retains a known committed generation through later panic/delivery failure/cancel. Synthetic transitions prove only the cell. ZE-68 must still use real native results/receipts and the actual preparation/coordinator path, test no allocation across its commit/delivery window, preserve core/ABI overlap, survive actual close/reopen without leases, and prove real outcomes under faults.
